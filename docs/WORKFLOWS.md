# Workflows

Step-by-step recipes for common changes. Follow the relevant recipe and run its verification steps.

## 1. Run and verify locally

```bash
npm install
npm run dev
```

Then:

```bash
curl -sI http://localhost:3000/ | head -1
curl -s  http://localhost:3000/api/health
```

Open the route in a browser and check the console. There is no automated test, lint, or typecheck command.

## 2. Add a new screen

1. Create a folder named after the screen, e.g. `my_new_screen_xadboom/`, and add `code.html`. Copy the closest existing screen as a starting point and keep its inline Tailwind config, header/footer/sidebar, motion assets, and `../src/prototype-navigation.js` script.
2. Register it in `SCREENS` in `server.js` (around line 364):

```js
{ id: 'my-screen', group: 'Storefront', label: 'My Screen', route: '/my-screen', file: 'my_new_screen_xadboom/code.html' }
```

Use the `Atelier Admin` group for admin screens so it appears in the admin nav group.

3. Mirror the entry in `src/prototype-navigation.js` (`screens` array, around line 8). Labels may be shorter there; keep `id`, `route`, and `file` aligned.

4. Add aliases if needed:
   - Server: extend the route registration block around `server.js:802`.
   - Static mode: extend `aliases` in `src/prototype-navigation.js:25`.

5. If the screen needs a sidebar entry, add the `data-path` or visible text and extend both mappings:
   - `server.js` injected map (`server.js:724-746`)
   - `src/prototype-navigation.js` `dataPaths` / `adminLinks` (`src/prototype-navigation.js:93-125`)

6. Verify:

```bash
curl -sI http://localhost:3000/my-screen | head -1
```

Also open the source file directly (or serve it statically) and confirm links resolve without Express.

Do not register a dynamic `/:something` route before the `/api/*` routes.

## 3. Rename or remove a route

1. Update `SCREENS` in `server.js`.
2. Update the mirrored `screens` array in `src/prototype-navigation.js`.
3. Update aliases in both files if they pointed at the old route.
4. Update injected link maps and any page-local `href` values that used the route.
5. Update `README.md` route table and `docs/PAGES.md`.

Search for the old route to catch hardcoded links:

```bash
rg "old-route" --glob '!node_modules'
```

## 4. Change shared prototype chrome (bottom nav, bag drawer)

Shared prototype chrome is generated by `enhanceHtml()` in `server.js:382`. This is the right place for:

- bottom quick-nav links
- reservation drawer markup and styles
- global bag/acquire/spec/form hooks
- admin link wiring

Make the edit inside the `injection` template, then verify every route (storefront and admin) still renders and the drawer still opens. This chrome does **not** exist in static mode; if the change must also work from `file://`, update `src/prototype-navigation.js` separately.

Do not add a second copy of the injection to individual pages.

## 5. Change a storefront header, footer, or admin sidebar

These are duplicated markup, not partials. Choose the scope:

| Scope | Files |
| --- | --- |
| Storefront header/footer | `index.html` plus `curated_architectural_assets_physical_typologies_xadboom/code.html`, `lumen_void_lounge_chair_product_detail_xadboom/code.html`, `designers_collaborating_visionaries_xadboom_1/code.html`, `designers_collaborating_visionaries_xadboom_2/code.html`, `contact_curatorial_inquiries_xadboom/code.html` |
| Admin sidebars | Each admin screen individually; the variants differ (`268px` text rail, `72-80px` icon rail, dark rail) |
| Footer shared link typography | `src/xadboom-motion.css` (`.xdm-footer-nav a`) |
| Active nav link style | `src/xadboom-motion.css` (`.xdm-nav-active`) |

Use `rg` to find all copies of a label or class before editing. Preserve each page's formatting; some admin files are intentionally dense/single-line.

## 6. Add an API endpoint

1. Add the handler in `server.js` near the other APIs (`server.js:177-361`).
2. Follow existing JSON conventions:
   - GET: return the resource array/object.
   - POST: return `{ success: true, ... }`.
3. Register the route before `app.get('/:dir')` and `app.use(express.static(...))`.
4. If it mutates state, update the in-memory structures and note the reset-on-restart behavior.
5. Document it in `docs/API.md` (method, body, response, defaults).
6. Update `GET /api/health` if the endpoint adds a meaningful count.
7. Smoke test with `curl`:

```bash
curl -s http://localhost:3000/api/your-endpoint
curl -s -X POST http://localhost:3000/api/your-endpoint \
  -H 'Content-Type: application/json' -d '{"key":"value"}'
```

## 7. Wire a page to an existing API

Preferred options, in order:

1. **Server injection** when the behavior should apply across pages (bag, spec, inquiries). Add the hook inside `enhanceHtml()` and guard against missing elements.
2. **Page-local script** when the behavior is screen-specific. Wrap it in an IIFE or `DOMContentLoaded`, use classic script syntax, and place it before `</body>`.

Example pattern:

```html
<script>
  (function () {
    var el = document.getElementById('my-action');
    if (!el) return;
    el.addEventListener('click', function () {
      fetch('/api/pieces')
        .then(function (res) { return res.json(); })
        .then(function (pieces) { /* update DOM */ });
    });
  }());
</script>
```

Remember that `fetch('/api/...')` only works through the Express server. If the page must also function from `file://`, hide or disable the network action when `location.protocol === 'file:'` or provide a static fallback.

Do not change the text of elements the injected hooks match (`bag`, `acquire`, `reserve`, `spec`, `3d`, `tear sheet`, `Add New Piece`) unless you also update the hook.

## 8. Add an animation or interaction

1. Add the behavior to `src/xadboom-motion.js` if it is generic; add a page-local script if it is screen-specific.
2. Add styles to `src/xadboom-motion.css` only for shared motion primitives or prototype chrome.
3. Opt in with data attributes instead of editing the script per page:
   - `data-reveal`, `data-reveal-delay`, `data-reveal-group`/`data-reveal-item`
   - `data-motion-header`, `data-motion-threshold`
   - `data-modal` + `data-modal-open` + `data-modal-card` + `data-modal-close`
   - `data-no-motion` / `data-no-roll` to opt out
4. Keep motion to transform/opacity, 150-420ms, no layout shift.
5. Verify with reduced motion enabled (`System Settings -> Accessibility -> Display -> Reduce motion`) and confirm content is visible.
6. Never edit `src/vendor/motion.js`.

## 9. Add an image

1. Put the file in `src/assets/images/`.
2. Reference it correctly:
   - Screen files (`*/code.html`): `../src/assets/images/file.ext`
   - Root `index.html`: `./src/assets/images/file.ext`
   - Server-generated HTML: `/src/assets/images/file.ext` (or rely on the `../src/` rewrite)
3. Prefer local assets for anything critical; remote `lh3.googleusercontent.com` URLs are unreliable offline and across environments.
4. Add descriptive `alt` text consistent with the page's editorial voice.
5. If replacing the hero, note the special case: `server.js:792-794` swaps one specific remote URL for `/assets/xadboom_hero_piece.jpg` on home and product.
6. Verify the image loads both served and from `file://`.

## 10. Change design tokens or restyle a page

1. Open the target page and find its inline `tailwind.config`.
2. Add or adjust the alias there; do not create a shared Tailwind config.
3. Use the page's existing token names before adding arbitrary hex values.
4. Use valid arbitrary syntax: `text-[#0A0A0A]`, `bg-[#FFF1EC]`, `border-[#D8C3BC]`.
5. Keep the page's radius/elevation contract (see `docs/DESIGN-SYSTEM.md` section 5).
6. For shared motion or nav/footer typography, use `src/xadboom-motion.css`.
7. Verify at mobile and desktop widths, and check that you did not reintroduce `text-#...` or `bg-#...` classes.

## 11. Change the reservation bag behavior

Files:

- `server.js:150-160` - state shape
- `server.js:162-174` - expiry interval
- `server.js:206-274` - cart endpoints
- `server.js:487-773` - injected drawer and hooks
- `docs/API.md` - contract to update

Rules:

- Keep the bag single-item unless you are deliberately changing the product model.
- Update `docs/API.md` and `ARCHITECTURE.md` if the state shape or lock semantics change.
- Test the full cycle: add -> drawer shows item and countdown -> release -> add -> checkout -> bag clears.
- Check the 400 response for checkout with an empty bag.

## 12. Debug common problems

| Symptom | Check |
| --- | --- |
| Route returns 404 | File path in `SCREENS`; file exists; case matches |
| Bottom nav missing under Express | Server injection intact; `enhanceHtml()` appends before `</body>` |
| Bottom nav missing in static mode | `../src/prototype-navigation.js` script present; file:// paths correct |
| Styles look unstyled | Tailwind CDN blocked; page config script error; invalid token alias |
| Arbitrary color ignored | Invalid syntax such as `text-#0A0A0A`; use `text-[#0A0A0A]` |
| Images broken | Remote URL dead or offline; local path wrong for the page depth |
| Bag button does nothing | Console error; button text no longer contains `bag`; `#xadboom-quick-nav` missing |
| Acquire button does nothing | Text no longer matches `acquire`/`reserve`; `href` points at `/catalog` or `#assets` |
| Spec/3D downloads wrong file | Injection sends matching buttons to the CSV endpoint by design |
| Form does not post | Form has `action` (hook skips it) or no email input; page-local handler calls `preventDefault` |
| Admin sidebar link dead | `data-path` not mapped; text label changed; add to both mappings |
| Page looks wrong from `file://` | Static navigator only; server injection (bag/spec/API) is unavailable |

## 13. Finish the task

1. Run the route and API smoke checks.
2. Review the diff for accidental formatting churn or unrelated files.
3. Update the docs listed in `AGENTS.md` under "Documentation upkeep".
4. Do not commit unless the user explicitly asks.
